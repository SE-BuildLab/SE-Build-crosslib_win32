The Marvin Attack (Hubert Kario, Red Hat) is a timing side-channel variant of the Bleichenbacher padding oracle attack against RSA PKCS#1 v1.5 decryption: an attacker who can measure the response time of a server decrypting attacker chosen ciphertexts can decrypt previously captured ciphertexts or forge signatures. For the OpenSSL API the oracle is the result itself - RSA_private_decrypt()/EVP_PKEY_decrypt() return an error (and a different output length) when the padding is invalid, and applications cannot handle this in a side-channel free way. The mitigation ('implicit rejection', as in OpenSSL 3.2) returns a deterministic pseudo random message derived from the private key and the ciphertext instead of an error, so that invalid padding is indistinguishable from a genuine random plaintext.

Marvin 攻撃 (Hubert Kario 氏、Red Hat) は RSA PKCS#1 v1.5 復号に対する Bleichenbacher パディングオラクル攻撃のタイミング変種で、攻撃者が選んだ暗号文を復号するサーバの応答時間を計測できれば、捕捉済み暗号文の復号や署名の偽造が可能になる。OpenSSL の API ではオラクルは結果そのもの、すなわちパディング不正時に RSA_private_decrypt()/EVP_PKEY_decrypt() がエラー (と異なる出力長) を返すことであり、アプリケーション側でサイドチャネル無しに扱うことはできない。対策 ('implicit rejection'、OpenSSL 3.2 と同じ) はエラーの代わりに秘密鍵と暗号文から決定的に導出した疑似乱数メッセージを返し、不正パディングを本物の乱数平文と区別不能にする。

4. Vulnerability / 脆弱性

rsa_ossl_private_decrypt() derives kdk = HMAC-SHA256(SHA256(d), ciphertext) unconditionally for RSA_PKCS1_PADDING, then ossl_rsa_padding_check_PKCS1_type_2() performs the constant-time PKCS#1 type 2 check and, using constant-time selects only, returns either the real message or a synthetic message of pseudo random length produced by an HMAC-SHA256 based PRF keyed with kdk. The classic behaviour remains available as RSA_PKCS1_NO_IMPLICIT_REJECT_PADDING / the EVP_PKEY_CTRL_RSA_IMPLICIT_REJECTION ctrl, and is used for engine keys without the private exponent and inside PKCS7/CMS recipient decryption (which rely on the error to detect a wrong key).

rsa_ossl_private_decrypt() は RSA_PKCS1_PADDING のとき無条件に kdk = HMAC-SHA256(SHA256(d), 暗号文) を導出し、ossl_rsa_padding_check_PKCS1_type_2() が定数時間の PKCS#1 type 2 検査を行い、定数時間 select のみを使って本物のメッセージか、kdk を鍵とする HMAC-SHA256 ベース PRF で生成した疑似乱数長の合成メッセージのいずれかを返す。従来の挙動は RSA_PKCS1_NO_IMPLICIT_REJECT_PADDING / EVP_PKEY_CTRL_RSA_IMPLICIT_REJECTION ctrl として残され、秘密指数を持たないエンジン鍵や、エラーで鍵の不一致を検出する PKCS7/CMS の受信者復号では従来挙動が使われる。

Affected: All OpenSSL releases before 3.2.0 (including 1.1.1w, 3.0.x) implement explicit rejection. Upstream does not plan to change stable branches (behaviour change); Ubuntu (1.1.1f-1ubuntu2.22) and Red Hat (RHEL 8 openssl-1.1.1k-12, RHEL 9.3) backported the mechanism to 1.1.1.

影響: 3.2.0 より前の全 OpenSSL (1.1.1w、3.0.x を含む) は明示的拒否のまま。上流は安定ブランチの挙動変更を行わない方針だが、Ubuntu (1.1.1f-1ubuntu2.22) と Red Hat (RHEL 8 openssl-1.1.1k-12、RHEL 9.3) は 1.1.1 系へバックポートした。

[EN] In pristine 1.1.1w, rsa_ossl_private_decrypt() (crypto/rsa/rsa_ossl.c) handles RSA_PKCS1_PADDING by calling RSA_padding_check_PKCS1_type_2() (crypto/rsa/rsa_pk1.c). The validity of the padding is therefore an explicit API signal (return value, output length, error queue, application behaviour), which is the oracle needed by Bleichenbacher / Marvin chosen-ciphertext attacks against RSAES-PKCS1-v1_5. The IPALongPatch 003 (semantic port of Ubuntu's openssl-1.1.1-pkcs1-implicit-rejection.patch, i.e. the Red Hat back-port of OpenSSL 3.2's PR #13817) makes RSA_PKCS1_PADDING compute, unconditionally, kdk = HMAC-SHA256(SHA256(d padded to |n|), ciphertext padded to |n|) and call the new ossl_rsa_padding_check_PKCS1_type_2(), which derives a synthetic message and a pseudo-random length from kdk with ossl_rsa_prf() and selects the real or the synthetic message with constant-time masks, so the API always "succeeds". The old behaviour is kept as padding mode RSA_PKCS1_NO_IMPLICIT_REJECT_PADDING (8), reachable through the new ctrl EVP_PKEY_CTRL_RSA_IMPLICIT_REJECTION / rsa_pkcs1_implicit_rejection:0 (crypto/rsa/rsa_pmeth.c), and is forced for engine keys (RSA_FLAG_EXT_PKEY) and by crypto/cms/cms_env.c and crypto/pkcs7/pk7_doit.c, whose callers need the error to detect a non-matching key.

[JA] 素の 1.1.1w では rsa_ossl_private_decrypt() (crypto/rsa/rsa_ossl.c) が RSA_PKCS1_PADDING に対して RSA_padding_check_PKCS1_type_2() (crypto/rsa/rsa_pk1.c) を呼ぶ。この関数は内部的には定数時間 (CVE-2022-4304 の強化) だが、復号ブロックが 00 02 || 8 バイト以上の非ゼロ || 00 || メッセージ の形でない場合は -1 を返し、呼び出し側は RSA_R_PKCS_DECODING_ERROR / RSA_R_PADDING_CHECK_FAILED をキューに入れ、RSA_private_decrypt() / EVP_PKEY_decrypt() は出力無しで失敗する。したがってパディングの正否が明示的な API 信号 (戻り値・出力長・エラーキュー・アプリケーションの挙動) になっており、これが RSAES-PKCS1-v1_5 に対する Bleichenbacher / Marvin 選択暗号文攻撃に必要なオラクルである。IPALongPatch 003 (Ubuntu の openssl-1.1.1-pkcs1-implicit-rejection.patch、すなわち OpenSSL 3.2 の PR #13817 の Red Hat バックポートの意味的移植) は、RSA_PKCS1_PADDING の場合に常に kdk = HMAC-SHA256(|n| 長にパディングした d の SHA256, |n| 長にパディングした暗号文) を計算し、新設の ossl_rsa_padding_check_PKCS1_type_2() を呼ぶ。同関数は ossl_rsa_prf() で kdk から合成メッセージと疑似乱数長を導出し、定数時間マスクで本物か合成かを選択するため、API は常に「成功」する。従来動作はパディングモード RSA_PKCS1_NO_IMPLICIT_REJECT_PADDING (8) として残され、新 ctrl EVP_PKEY_CTRL_RSA_IMPLICIT_REJECTION / rsa_pkcs1_implicit_rejection:0 (crypto/rsa/rsa_pmeth.c) で選択でき、エンジン鍵 (RSA_FLAG_EXT_PKEY) と、鍵不一致の検出にエラーを必要とする crypto/cms/cms_env.c および crypto/pkcs7/pk7_doit.c では強制される。

PoC design / PoC の設計

[EN] gen_inputs.sh creates an RSA-2048 key, two valid PKCS#1 v1.5 ciphertexts of "Hello Marvin", a copy of the first with its last byte flipped, and raw-RSA (no padding) encryptions of crafted blocks (make_blocks.py, run with python3 -I): block type 0x01, no 0x00 separator, only 3 padding bytes, non-zero first byte, plus a hand-made valid block as control. poc_rsa.c (built once per build) decrypts each file with RSA_private_decrypt(RSA_PKCS1_PADDING) twice (determinism), EVP_PKEY_decrypt() with defaults, with rsa_pkcs1_implicit_rejection:0 (string ctrl) and with EVP_PKEY_CTRL_RSA_IMPLICIT_REJECTION=0, and with padding mode 8; it prints length, first bytes and SHA-256 of each output or the error string. --timing N interleaves N decryptions of the valid and of the corrupted ciphertext and prints min/quartiles/median/mean. run_poc.sh runs, for BASE and PATCHED: the CLI (pkeyutl -decrypt twice on the corrupted ciphertext, rsautl -decrypt, -pkeyopt rsa_pkcs1_implicit_rejection:0), the C PoC, test/evp_test on the patched tree's evppkey.txt (OpenSSL 3.2 implicit-rejection vectors, identical to the Ubuntu patch's 156 vector lines), the timing run (5000+5000), CMS and PKCS#7 encrypt/decrypt with the right and a wrong key (incl. cms -decrypt -debug_decrypt), a TLS 1.2 AES128-SHA (RSA key exchange) handshake, and valgrind on the patched PoC.

[JA] gen_inputs.sh は RSA-2048 鍵、"Hello Marvin" の正当な PKCS#1 v1.5 暗号文 2 個、最初の暗号文の末尾バイトを反転したもの、細工ブロックの生 RSA (パディング無し) 暗号化 (make_blocks.py、python3 -I で実行) を作る: ブロック種別 0x01、0x00 区切り無し、パディング 3 バイトのみ、先頭バイト非ゼロ、対照として手作りの正しいブロック。poc_rsa.c (ビルドごとにコンパイル) は各ファイルを RSA_private_decrypt(RSA_PKCS1_PADDING) で 2 回 (決定性)、既定の EVP_PKEY_decrypt()、rsa_pkcs1_implicit_rejection:0 (文字列 ctrl)、EVP_PKEY_CTRL_RSA_IMPLICIT_REJECTION=0、パディングモード 8 で復号し、出力の長さ・先頭バイト・SHA-256 またはエラー文字列を表示する。--timing N は正当/改変暗号文の復号を N 回ずつ交互に行い min/四分位/中央値/平均を表示する。run_poc.sh は BASE と PATCHED それぞれで、CLI (改変暗号文に対する pkeyutl -decrypt 2 回、rsautl -decrypt、-pkeyopt rsa_pkcs1_implicit_rejection:0)、C PoC、パッチ版ツリーの evppkey.txt (OpenSSL 3.2 の implicit rejection ベクタ、Ubuntu パッチの 156 ベクタ行と同一) に対する test/evp_test、タイミング (5000+5000)、正しい鍵/誤った鍵での CMS と PKCS#7 の暗号化/復号 (cms -decrypt -debug_decrypt 含む)、TLS 1.2 AES128-SHA (RSA 鍵交換) ハンドシェイク、パッチ版 PoC への valgrind を実行する。

Limitations / notes / 制約・注記

[EN] (1) No CVE is assigned to OpenSSL for this item (the Marvin page lists "OpenSSL (API level): No CVE"); the issue is an API-level oracle, so there is no crash/ASan/gdb artefact — the evidence is behavioural. (2) The timing measurement did not show a significant valid-vs-invalid difference in either build on this shared 4-vCPU VM (differences of −1.3 %…+0.04 % of the median, varying in sign between runs); 1.1.1w's padding check was already constant time (CVE-2022-4304), so the Marvin oracle in 1.1.1 is primarily the explicit error/length signal, which is what the patch removes. (3) Interoperability with OpenSSL 3.2 was shown through the 3.2 test vectors contained in the patch (verified identical to the Ubuntu patch), not against a live 3.2 binary (none is available offline). (4) The PKCS#7 wrong-key path cannot distinguish the two builds by its output (the MMA-defence random key leads to "bad decrypt" either way); the CMS -debug_decrypt run is the observable confirmation of the "keep explicit rejection" hunks. (5) The first two script attempts failed for environmental reasons (missing xxd, req needing -config, S/MIME CRLF canonicalisation) and are kept in the log as history.

[JA] (1) 本項目について OpenSSL に CVE は割り当てられていない (Marvin ページは "OpenSSL (API level): No CVE" としている)。問題は API レベルのオラクルであり、クラッシュ/ASan/gdb の成果物は無く、証拠は挙動的なものである。(2) この共有 4 vCPU VM では、いずれのビルドでも正当/不正の有意なタイミング差は観測されなかった (中央値の −1.3 %〜+0.04 %、実行ごとに符号が変わる)。1.1.1w のパディング検査は既に定数時間 (CVE-2022-4304) であり、1.1.1 における Marvin オラクルは主として明示的なエラー/長さ信号であって、パッチが除去するのはそれである。(3) OpenSSL 3.2 との相互運用性はパッチに含まれる 3.2 のテストベクタ (Ubuntu パッチと同一であることを確認) で示したもので、実際の 3.2 バイナリとの対向試験ではない (オフラインのため入手不可)。(4) PKCS#7 の誤鍵経路は出力では両ビルドを区別できない (MMA 対策のランダム鍵によりいずれも "bad decrypt")。「明示的拒否を維持する」ハンクの観測可能な確認は CMS の -debug_decrypt 実行である。(5) スクリプトの最初の 2 回の試行は環境要因 (xxd 不在、req の -config 必須、S/MIME の CRLF 正規化) で失敗し、履歴としてログに残している。
